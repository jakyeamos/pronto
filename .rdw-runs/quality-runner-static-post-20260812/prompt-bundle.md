## Router Prompt

# Domain Router

Infer the full task contract from natural language. **The user does not need to pass `domain=`, `entity=`, etc.** — only when they want to override.

## Inputs

- User writing request (raw) — may be a single sentence
- Optional explicit overrides (`domain=`, `entity=`, `output-type=`, `audience=`, `depth=`, `packet-id=`)
- `config/domains.yaml`
- `config/router-inference.yaml`
- List of available packs under `domains/`
- Optional: project paths, files, or URLs the user mentions (load for entity context)

## Inference procedure (required)

1. **Start from** `config/router-inference.yaml` defaults.
2. **Parse user text** for domain signals (jargon, surface names like "LIS leaderboard", product names).
3. **Apply** `domain_inference` keyword lists → pick domain with most signals; if tie, prefer basketball only when sports/stat cues present.
4. **Apply** `output_type_inference` and `entity_inference` patterns (e.g. "leaderboard" → `ranking_explanation`, entity `LIS leaderboard` if named).
5. **Apply** `audience_inference` match lists.
6. **Apply** `depth_inference`: deep triggers win; light triggers win; else `standard`.
7. **Explicit overrides** from `key=value` or user saying "domain is X" → replace inferred field; set `mode: mixed`.
8. **Entity naming**: preserve user’s proper nouns (LIS, product names) verbatim in `entity_name`.
9. **Topic**: short phrase for what the writing must accomplish (e.g. "improve leaderboard UI copy").
10. **Do not invent domain facts** — only route metadata. Unknown domain → `general` + warning.
11. **Do not equate presence with maturity** — `pack_exists` only proves resolution.
    Surface `pack_readiness`; a specialized pack with `ok: false` cannot support
    production drafting until its deterministic pack gate passes.
12. **Do not equate packet presence with reusability** — use the deterministic
    `packet_resolution` projection. Only `action: reuse` may skip research. Missing,
    stale, incompatible, insufficient, legacy, conflicted, or review-required packets
    must create/refresh a candidate or stop for review as projected.

## After routing

- **Show the inferred contract** to the user in a compact table; proceed unless they object.
- Continue pipeline without requiring them to re-type parameters.

## Rules

- Prefer reusing `knowledge/<domain>/*.yaml` when packet id matches entity (e.g. `basketball-lis-leaderboard` if exists).
- Reuse that path only when `packet_resolution.action: reuse`; otherwise preserve the
  current head and follow `next_safe_step`.
- Flag `warnings` when `inference.confidence` is low.
- Never block the run solely because parameters were omitted.


## Pipeline Orchestrator

# Pipeline Orchestrator (Single Task)

Run the full research-domain-writing pipeline for one task.

## Research & batch

- **Research:** agent executes `researcher.md` (may use any tools); skill saves structured packets (`docs/LIMITATIONS.md`).
- **Batch (v0.1):** `rdw batch plan <batch.yaml>` creates task bundles; agent follows `prompts/batch-runner.md` to execute them.

## Load order

1. `config/domains.yaml`, `config/router-inference.yaml`, `config/style-profile.yaml`, `config/output-formats.yaml`
2. `prompts/domain-router.md` → router output (**infer** domain, entity, output_type, audience, depth from user text if omitted)
3. Present inferred contract to user; proceed without requiring `key=value` args
4. For a specialized pack, require `pack_readiness.ok: true` (or run
   `rdw validate-pack <domain>`). `pack_exists` alone is insufficient, and only
   acceptance-backed `production_output_types` may claim mature support.
5. Enforce `packet_resolution.action` before research or drafting:
   - `reuse`: skip research and use the accepted head;
   - `create_candidate`: research a new run-local candidate;
   - `refresh_candidate`: preserve the head and research a child candidate; or
   - `resolve_review`: stop confident drafting until explicit resolution.
6. If research needed: `prompts/research-planner.md` → `prompts/researcher.md`
7. `prompts/knowledge-packet-builder.md`
8. For create/refresh, promote the candidate with `rdw packet promote`, then regenerate
   the task contract and require `packet_resolution.action: reuse`.
9. `rdw research-readiness <packet> --contract <task-contract> --json` — separate
   source, packet, output, and output-specific research sufficiency. Continue research
   until `writing_material_ready` and `can_draft_confidently` are true.
10. `prompts/domain-copywriter.md`
11. `prompts/domain-qa.md` — emit the exact-draft hash, universal prose-block claim
   ledger, and stable rule results; run `rdw validate-claim-ledger ... --draft ...`
12. Compare packet/draft against an approved diff baseline; only `pass` may enter `qa-passed`
13. `prompts/humanizer-blader.md`
14. Save artifacts per `config/output-formats.yaml`
