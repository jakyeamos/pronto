# Change Radius route plan

Status: C0 public Showcase admission is complete; the current real-fixture and
unknown-boundary proof are verified while downstream parity remains gated.

The [canonical target](../ideal-demo-targets.md#change-radius) owns the
promise and proof gate. The map is deliberately bounded and refuses a universal
blast-radius claim.

## 1. Ideal target

**North star:** a reviewer follows one changed TypeScript symbol to known
consumers and tests while seeing dynamic, generated, external, and reflective
unknowns explicitly.

**Non-negotiable:** provider-named static edges are not proof of runtime use,
and unknown consumer classes remain visible.

## 2. Concept materials

The current real-fixture frame is locally verified; downstream links and the
negative matrix remain gated.

| Frame          | Visual                                                  | On-screen line                 | Intended evidence moment          |
| -------------- | ------------------------------------------------------- | ------------------------------ | --------------------------------- |
| 1. Change      | One exported symbol is selected in a diff               | “Start with the changed thing” | Scope is concrete                 |
| 2. Known edges | Consumers and tests appear with provider names          | “Follow what we can prove”     | Evidence is useful                |
| 3. Unknowns    | Dynamic, generated, and external boundaries are labeled | “Blind spots stay visible”     | Partial evidence is not certainty |
| 4. Receipt     | Target, graph, and next review surface are linked       | “Carry the radius forward”     | Handoff is durable                |

**Preview concept.** Use a diff-centered graph with solid known edges and a
separate unknown panel. Avoid a single risk score.

**Narrative spine.** Changed symbol → known consumers/tests → unknown classes →
source-bound receipt.

## 3. Build-gap specification

Reviewed baseline: the current `dev` head passes tests, lint, and packaging and
exposes a bounded static consumer/test graph, provider names, and explicit
unknown classes on a real TypeScript fixture. Cross-tool boundaries remain
open.

Project disposition: `targeted_gap_closure` — run one real TypeScript fixture
and connect the unknown boundary to Deletion Proof and Contract Watch.

Gap classes: evidence — CR-0; demo_integration — CR-1; product — CR-2;
packaging — CR-3.

| ID   | Gap to close                    | Observable acceptance condition                                                             | Owner                | Required proof               |
| ---- | ------------------------------- | ------------------------------------------------------------------------------------------- | -------------------- | ---------------------------- |
| CR-0 | Validate the bounded fixture    | Known consumers, tests, and dynamic/external unknowns appear for one real TypeScript change | Evidence owner       | Target-bound graph receipt   |
| CR-1 | Connect downstream review tools | The same symbol and unknown classes reach Deletion Proof and Contract Watch                 | Integration owner    | Cross-tool links and parity  |
| CR-2 | Preserve graph limitations      | Generated, reflective, and external edges cannot be silently promoted to known              | Product/safety owner | Negative fixture matrix      |
| CR-3 | Package the public case         | Binary preview, short copy, no-auth graph case, and proof link agree                      | Showcase owner       | Material review and readback |

**Required build order:** CR-0 → CR-1 → CR-2 → CR-3. Video is optional after
the evidence gate.
