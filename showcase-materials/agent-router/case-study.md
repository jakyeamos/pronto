# Agent Router: route complex AI work with reasons

## The case

The headline case is a labeled synthetic launch-readiness request. It asks for
a repository change and focused tests while preserving an explicit human
approval boundary for writes. The safe replay fixture turns that request into
three typed nodes:

`plan → execute → verify`

The native planner carries the authority constraints on the typed intent. The
candidate packet compares task-specific evidence rather than pretending that a
model name is a quality score. Codex and Cursor have observed replay evidence;
Antigravity stays eligible but weakly evidenced. Other candidates remain
visible with their actual availability, capability, or quality-floor reason.

The bounded execution appendix keeps the result attributable. Each selected
subtask has one synthetic worker receipt with a provider identity, result, and
fixture evidence. It records zero provider invocations and zero worktree
mutations, so the replay is useful without masquerading as a live run.

## Where the proof stops

The conflict probe is the important limitation. Two worker receipts disagree,
so the native engine labels the conflicts and selects `model_synthesis`. The
current `SynthesisDecisionSchema` does not yet expose a final confidence or
fallback decision. That is AR-5, and this packet keeps it visible instead of
turning the mode label into an outcome claim.

The compact synthetic fixture is the reproducibility appendix, not a customer
engagement. The public material can show how the route is chosen and where
disagreement enters the receipt. It cannot claim that a provider ran, a
worktree changed, or a launch-readiness result was delivered until those
boundaries have their own evidence.
